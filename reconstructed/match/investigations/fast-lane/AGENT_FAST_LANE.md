# OpenPizza2 — high-throughput, low-token matching protocol

## Mission
Maximize **new, non-overlapping, strict-matched `.text` bytes per hour / per AI token**. Do not optimize the number of attempts, prompts, or touched families. The original `fastfood2.exe` SHA-256 must be `18cfd32e0ac5d6d98162ec016e058a2b51808d9ca49ebee933ce3166ff9922fd`. Use the repository-pinned VC6 SP3 and the existing `--strict --auto-symbols` matcher. Never claim a strict match from an approximate disassembly similarity, same-length output, or non-strict verification.

## Before every batch, synchronize information, not working files
1. `git fetch origin main --quiet` (read-only fetch; **do not** `git pull` over an active/dirty checkout).
2. Record `git rev-parse HEAD`, `git rev-parse origin/main`, `git status --short`, `git log -5 --oneline origin/main`.
3. If upstream advanced, inspect `git diff --name-status HEAD..origin/main -- reconstructed/match tools` and avoid families actively changed upstream. Rebase/merge only from a clean worktree and under the local development policy.
4. Read `AGENTS.md`, `CONTRIBUTING.md`, `reconstructed/match/VC6_TOOLCHAIN.md`. Skip already solved verifiers/generators. Keep compiler, C2, Wine environment and `--flags` unchanged unless evidence requires a variant.

## Refresh coverage inventory **once per HEAD**, not per candidate
Use the repository's current tools and cached evidence; don't generate new broad disassembly each time.

```bash
# Full baseline audit at start of a fresh HEAD or a milestone; costly.
python3 tools/audit_matches.py --out /tmp/pc2-audit-base --jobs 8
python3 tools/map_vc6_cleanup_families.py --out /tmp/pc2-cleanup.json
python3 tools/mine_feature_families.py --out /tmp/pc2-features.json --report /tmp/pc2-features.md
python3 tools/build_family_registry.py \
  --inventory /tmp/pc2-cleanup.json \
  --features /tmp/pc2-features.json \
  --audit /tmp/pc2-audit-base \
  --out /tmp/pc2-registry.json --report /tmp/pc2-registry.md \
  --specs-out /tmp/pc2-family-specs
python3 tools/roi_family_queue.py \
  --registry /tmp/pc2-registry.json --audit /tmp/pc2-audit-base \
  --out /tmp/pc2-queue.md --json-out /tmp/pc2-queue.json
```

If some repository commands/paths have changed upstream, adapt against their current `--help` or `CONTRIBUTING.md`; don't run stale commands blindly. `roi_family_queue.py` gives *candidate* and *missing* byte quantities and removes repeated addresses. It does not forecast success or certify additional matches. Family membership by shared cleanup or call target is only a discovery lens; it is **not** proof of shared source shape.

## Two-lane scheduling
- **Lane A (cheap/fast):** rank already sourced but not strict candidates by ready bytes and structural similarity. Batch compile and compare deterministically, fix obvious shared issues, then promote strict receipts. Avoid one-byte register allocation walls unless the pattern generalizes.
- **Lane B (big wins):** group missing functions by normalized instruction shapes, object layouts, shared vtable/EH patterns, sequences of imported calls, and compiler structure. Prioritize groups with large **unique** unfinished byte total and a plausible generator. A broad `Mem_Free` cleanup grouping is only an upper bound; subdivide by structural fingerprint first. Never add overlapping family byte ceilings.

## Generator proof gate (hard rule)
1. Pick one simple, one typical, and one *held-out* family member.
2. Derive one readable C/C++ generator/template; keep the held-out member out of design.
3. Verify strict (`tools/match_decomp.py` / `tools/run_family_batch.py`, including all relocations and secondary sections).
4. **Scale only if the held-out case matches unmodified except for legitimate per-member configuration.**
5. If none match after a bounded search, record exact blockers, label as nonmatching, and move on.

## Cost control (hard rule)
- Run repetitive compiler combinations and diffs **outside the model**. Use deterministic bounded source-shape enumerations / local permuter where allowed by `CONTRIBUTING.md`.
- Reuse the existing persistent COFF cache: `--cache /tmp/pc2-coff-cache` and choose a fresh `--out` directory each run; `tools/run_family_batch.py` creates `out/objects` without `exist_ok`, so reusing the output directory fails.
- `--jobs 4` initially; benchmark 4 vs 8 if compiler throughput is limiting. Don't assume 8 is always faster under Wine.
- Do not run `verify_all.py` or the global strict audit after every single edit. Run the **affected** verifier per iteration, and full baseline/regressions at commits or milestones.
- Never feed full objdump or entire audit logs into a reasoning model. Construct a compact machine-readable **diagnostic packet** per structural cluster: target addresses, instruction prefixes, lengths, source shape, flags, generated bytes/diff count, first 3 disassembly mismatches, relocation/EH blockers, up to 5 previous source variants and outcomes. 3–10KB per packet, not megabytes.
- When a proposal does not change the mismatch fingerprint, do not repeat it. Keep an append-only `attempts.jsonl` keyed by `(exe SHA, VC6 provenance, address, normalized-source-hash, flags, tool version)`.
- Apply a hard escalation limit: after ~6–10 failed attempts per *shape*, summarize the blocker once and switch to another family. The exact limit may be adjusted from measured strict bytes/hour.
- Use a cheap model for template instantiation and syntax; use a strong reasoning model **only** when a high-potential cluster has a genuinely new mismatch not explainable by deterministic rules.
- Print concise checkpoints only: <=500 words, containing HEAD, candidate family, new strict addresses, newly strict non-overlapping bytes, time spent, cache hits, and the next bottleneck. No long chronological tool transcripts.

## After each successful family batch
1. Add legitimate source/generator, strict verification receipts and compact first-diff evidence; no forged object patches/inline ASM tricks.
2. Run the changed family verifier and the relevant regression set.
3. Update the matching inventory from latest HEAD; recompute **new union of strict `.text` address ranges**; report percentage delta using current PE `.text` size and subtract the baseline. Only count strict addresses once. If relocs/secondary sections fail, count zero.
4. Commit a focused, fully tested change if permitted by local agent's workflow.
5. Fetch `origin/main` again; adapt priorities to any new upstream commit before starting the next family. Never overwrite other agents' work.

## First concrete action
Refresh the upstream HEAD, read the full snapshot of tracked strict coverage, and run `tools/roi_family_queue.py`. Pick the top structurally coherent **high-byte** unfinished group. Do a three-member proof pilot. If successful, turn it into a generator and match as many as possible. Do not spend a session cleaning up low-byte one-offs while a plausible multi-kilobyte family is available.

## Scorecard
Report `new strict unique .text bytes`, `baseline strict .text bytes`, `total .text bytes`, `percentage-point delta`, `wall-clock minutes`, and (where measurable) `tokens used`. Keep an explicit distinction between theoretical family gap and newly *verified* gains.
