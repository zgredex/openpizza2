## EH findings

The three C++ EH functions are reproducible with genuine C++ source; no
instruction-level asm is needed:

* Compile with `/GX`. A local object with a destructor (or a `new` expression
  whose class has a destructor) installs the standard FS-based frame and C2
  emits a `.text$x` funclet + handler thunk plus a `.xdata$x` FuncInfo.
* When the source is structurally right, those compiler-generated bytes are
  byte-identical to the shipped image. `match_decomp.py --strict` locates them
  through the original handler immediate (`push <handler>`) and verifies
  21-byte / 40-byte secondary spans. The matcher reports them as
  `derived_section_anchor`.
* Constructors with a member subobject reproduce the shipped member-destroy
  funclet only when the member offset, the member constructor and destructor
  calling convention match. `Storage` needed a 4-byte vptr pad (manual store)
  so the member sits at +0x44.
* A `new` expression stores the allocation pointer in the argument slot the
  EH cleanup funclet reads (`[ebp+0x10]` for `UI::CreateMovieWindow`). The
  frame is a params struct passed by address; making the 4th argument part of
  that struct was the change that reproduced both the temp slot and the
  cleanup offset.
