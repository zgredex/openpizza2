# `.spr` sprite format and decoder

`Sprite_Load` (`0x53c7f0`) reads a 0x21-byte header, then raw or alpha/RLE pixel
data. The compressed path is confirmed by the blitter `FUN_0053a780` and the
collision scanner `FUN_0053d720`; `FUN_0053d4b0` only converts RGB555→RGB565 and
is skipped when the alpha/RLE flag is set.

## Header (0x21 bytes)

| Offset | Type | Meaning |
|---|---|---|
| `0x00` | `u32` | pixel-stream size (8bpp: excludes the 0x300-byte palette) |
| `0x04` | `u8` | format byte |
| `0x05` | `u8` | flags; bit `0x10` = alpha/RLE token stream |
| `0x06` | `u8` | bits per pixel: `8` or `16` |
| `0x07` | `u16` | row stride in bytes |
| `0x09` | `u16` | image height |
| `0x0B` | — | hotspot/metadata |
| `0x13` | `u16` | canvas width |
| `0x15` | `u16` | canvas height |
| `0x19` | `u32` | pixel-stream size (duplicate of `0x00`) |
| `0x1D` | `u32` | transparent color key for raw 16bpp (usually `0x03e0`) |
| `0x21` | `byte[]` | payload |

Image width = `stride / (bpp / 8)`. The canvas fields can be larger than the
actual image (for overlays such as hair/faces).

## Payload

- **8bpp:** the pixel stream comes first; the 256-entry BGR palette follows it
  at file offset `0x21 + pixel_stream_size`. `Sprite_Load` reads `data_size +
  0x300` bytes and calls `Palette_Init` at `buffer + data_size`.
- **16bpp:** no palette; raw RGB555 or alpha/RLE tokens.
- **Raw 16bpp:** little-endian RGB555; pixels equal to the color key are transparent.
- **Raw 8bpp:** one byte per palette index. When the stream is shorter than
  `width * height`, `<colour-key> <run>` skips `run` transparent pixels. The
  collector byte is the sprite header's colour key (`0xff` for city sprites,
  `0xE6` for some icons), not a fixed `0xff`. This is the format used by
  `b_laub_b.spr`, `laternekl04_2.spr` and `w_buerf_ger2.spr`.
- **8bpp alpha tokens (`flags & 0x10`):** two bytes per token, `u8 alpha,
  u8 index`; `alpha == 0` skips `index` pixels.

### Alpha/RLE tokens (`flags & 0x10`)

| bpp | Token | Meaning |
|---|---|---|
| 8 | `u8 alpha`, `u8 index` | `alpha==0`: skip `index` pixels; else one palette pixel |
| 16 | `u16 alpha_word`, `u16 rgb555` | `alpha_word==0`: skip `rgb555` pixels; else one pixel |

- Alpha byte = `alpha_word >> 8` for 16bpp.
- Alpha `0x3c` means fully opaque; lower values are alpha-blended by the engine.
- Decoding is sequential row-major; transparent runs advance the destination.

## Tool

```bash
python3 tools/spr_tool.py info  extracted/sprites/pizzaimages/haare_f_08.spr
python3 tools/spr_tool.py list  extracted/sprites --filter stimmung
python3 tools/spr_tool.py export extracted/sprites path/to/pngs
python3 tools/spr_tool.py export extracted/pictures path/to/pngs --limit 20
```

`export` writes RGBA PNGs with a built-in zlib PNG writer (no Pillow needed).
Named sprite-layer pseudocode is exported in `spr_layer_final/` (`Sprite_Load`,
`Sprite_BlitAlphaRLE`, `Sprite_Rotate`, `Sprite_TestCollision`, palette/hotspot
accessors).

Validated examples:

- `haare_f_08.spr` — 32×20, 16bpp alpha/RLE, 640/640 pixels covered; renders as a hair overlay.
- `head_f_01.spr` — 60×50, raw 16bpp; renders as a face.
- `statistikfilialbilanz.spr` — 800×600, raw 16bpp; renders as the statistics background.
- `logos__04.spr` — 25×23, 8bpp palette + tokens; decodes, but palette/alpha
  appearance is best-effort.

Counts: 6,947 `.spr` files in the extracted tree; 6,817 are 8bpp, 130 are 16bpp.
A full-corpus export produced **6,947 PNGs / 65 MB** in `../extracted_png/`, with `SHA256SUMS` generated by the corrected decoder; the
only skip is `isodaten/sprites/blinki.spr`, which declares 0×0 dimensions.

## Limits

- 8bpp palette order and alpha blending are inferred from `FUN_00535e50` and
  `FUN_0053a780`; the palette follows the pixel stream, not the header.
- Some 8bpp files are sparse masks (all-transparent tokens); `blinki.spr` is a
  valid blank `0x0` sprite with a 64x64 canvas.
- The Python exporter originally read the palette from the start of the payload,
  which preserved silhouettes but produced noisy colours. `tools/spr_tool.py`
  now matches `Sprite_Load` and the Rust decoder; both produce these hashes:

```text
8bpp  b_laub_b.spr  144x106  0x8c144b3bf0b94e51
16bpp pb07__01.spr   29x29   0x4b1da7c6da626011
```
- PNG export is a static decode; it does not reproduce engine blending onto a
  destination surface.
